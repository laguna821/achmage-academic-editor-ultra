# Academic Editor Ultra 시작하기

## 입구

Obsidian 명령 팔레트에서 **Achmage Academic Editor Ultra: 저널 Markdown 원고 만들기**를 실행하세요. 왼쪽 리본의 **Academic Editor Ultra** 아이콘으로도 열 수 있습니다.

새 플러그인 설치 직후에는 커뮤니티 플러그인 설정에서 **Achmage Academic Editor Ultra**를 켜야 합니다. 기존 HanMark PDF 버튼은 일반 문서 출력용입니다.

## 새 Markdown 원고

1. **새 Markdown 원고**에서 공개 기본 프리셋 또는 가져온 사용자 템플릿을 선택합니다.
2. 왼쪽 **원고 편집**에서 제목·저자·초록·발행정보를 입력합니다. 각 항목에 출력 위치, 예시, 저널 필수·권장·선택 표시와 **도움말**이 있습니다. YAML 키를 찾을 필요가 없습니다.
3. 평소처럼 `##` 본문 절, `###` 하위 절, Markdown 표와 이미지를 씁니다. 로컬 이미지와 CMDS Eagle에서 받은 HTTPS/R2 이미지 링크를 그대로 사용합니다.
4. 위쪽 **↻ 미리보기 갱신**을 누릅니다. 미리보기의 제목·초록·교신저자 등을 클릭하면 왼쪽 입력란으로 이동합니다. 본문을 클릭하면 원문의 해당 위치로 이동합니다.
5. 검사 결과를 확인하고 **검토용 PDF**, **최종 PDF**, **IDML**, **AF** 중 필요한 출력을 선택합니다.

```yaml
aaeu-title: "논문 제목"
aaeu-abstract: |
  초록의 첫 문단입니다.

  둘째 문단도 보존됩니다.
aaeu-received: "2026-09-18"
aaeu-corresponding-name: "교신저자 이름"
aaeu-corresponding-email: "author@example.org"
aaeu-corresponding-address: |
  소속과 주소
aaeu-data-text: |
  실제로 확인한 Data Availability Statement를 입력합니다.
```

날짜와 이메일은 예시입니다. 확인한 값으로 바꾸세요. 위 YAML은 **전체 YAML · 고급 보기**나 원래 Obsidian 노트에서 직접 편집할 때의 예입니다. 안내형 입력과 같은 `.md`를 수정하며, 다른 플러그인의 속성과 주석을 유지합니다. 전체 항목은 [속성 매핑](markdown-properties.md)과 [전체 템플릿](../templates/journal-manuscript.md)에 있습니다.

## 입력과 미리보기 갱신

원고는 입력을 멈춘 뒤 500ms 후 저장됩니다. **기본값에서는 타이핑할 때 조판하지 않습니다.** `수정사항 있음` 표시가 보이면 **↻ 미리보기 갱신**을 누르세요. **자동 갱신**을 켜면 2초 동안 입력이 없을 때 조판합니다. PDF 출력 전에는 최신 원고로 다시 조판합니다.

열린 원본 노트도 동기화합니다. 외부 수정과 같은 부분을 고쳤다면 양쪽 내용을 보여주고 내 편집의 별도 사본을 보관합니다. 충돌을 해결하기 전에는 이전 미리보기를 최신 결과로 출력하지 않습니다.

## 템플릿과 시험 출력

상단 템플릿 목록에서 선택하면 즉시 적용합니다. **템플릿 만들기·수정**을 사용할 때만 위자드가 열립니다. 원고별 직접 입력·숨김 설정은 템플릿을 전환해도 유지됩니다. 이전 프로젝트의 YAML과 지면 템플릿이 다르면 사용할 쪽을 고릅니다.

**검토용 PDF**는 미입력·미확인 경고가 있어도 저장합니다. **최종 PDF**는 남은 항목을 모아 보여주며 **그래도 출력**을 선택할 수 있습니다. 이 선택은 검사 통과로 기록하지 않습니다. 비어 있는 교신저자·날짜·선언문은 표제와 누락 안내 문구까지 출력에서 숨깁니다. 그림 누락은 계속 경고합니다. 잘못된 YAML이나 실제 PDF 생성 실패는 먼저 고쳐야 합니다.

## 반복 정보와 문구

- 저자·소속·오른쪽 사용자 정보·추가 선언문은 안내형 화면의 **추가 / 삭제** 버튼으로 관리합니다.
- `aaeu-header-even-text`, `aaeu-header-odd-text`는 2페이지 이후 머리말을 바꿉니다. `aaeu-folio-text`에는 `{page}`를 사용할 수 있습니다.
- `aaeu-publication-mode: aop`는 권호·쪽수 표시를 억제하고 입력값은 보관합니다. 정식 권호 출력은 `issue`와 시작 페이지를 지정합니다.
- 머리말·판권 등의 문구는 **템플릿 기본값 / 직접 입력 / 숨김** 중에서 선택합니다.
- DAS·Funding·Conflict of Interest·Acknowledgments 등은 References 앞에 배치됩니다.
- 초록 옆에는 `aaeu-sidebar-1-label`, `aaeu-sidebar-1-text`로 사용자 정보를 추가합니다. 순서는 `aaeu-sidebar-order`로 지정합니다.

## 기존 원고

기존 Markdown 노트를 열고 **현재 Markdown 원문으로 저널 시작**을 실행하세요. 원래 YAML을 지우지 않으며, 안내형 입력란에서 필요한 항목을 채울 수 있습니다. 이미지 URL의 실제 내용이 바뀌었다면 **원격 이미지 새로고침**을 누릅니다.

저자의 Word는 **새 Word 편집본**에서 시작합니다. 이 경로는 본문 편집기를 사용합니다. **HanMark 프로젝트 복사**는 기존 원고와 템플릿을 별도 폴더로 복사하므로 원본은 유지됩니다. 기존 Markdown 편집본에서 수동 수정한 내용도 자동으로 버리지 않습니다.

AF는 디자인 도구에서 마지막 수정을 이어가기 위한 파일입니다. AF에서 한 수정이 원본 Markdown에 반영되지는 않습니다.

## CMDS Eagle과 R2 이미지

일반 Markdown 이미지 주소와 로컬/위키 이미지 임베드를 사용합니다. 원격 이미지도 가져오면 프로젝트의 그림이 되므로 미리보기에서 이동·크기 조절할 수 있습니다. 원격 파일의 실제 바이트를 저장한 사본으로 조판합니다.

통합 본문 편집기는 Obsidian의 `editor-paste` / `editor-drop` 이벤트를 전달합니다. CMDS Eagle을 켜고 클라우드 붙여넣기를 설정했다면 내부 편집기에서도 그림 붙여넣기로 주소를 받을 수 있습니다. CMDS Eagle 1.8.4의 실제 붙여넣기 처리기를 격리 볼트에서 검증했으며 업로드 서버만 시험 응답으로 대체했습니다. 실제 R2 계정에 업로드하는 시험은 하지 않았습니다.

CMDS Eagle의 모든 명령을 대체하지는 않습니다. 기본 Obsidian Markdown 탭을 요구하는 검색·전체 이미지 변환 명령은 **원문 열기**에서 실행하세요. 업로드와 인증은 CMDS Eagle이 담당합니다.

## 표·그림 배치

선택한 표·그림은 **왼쪽 칼럼 / 오른쪽 칼럼 / 전체 폭**에 맞춥니다. 위아래로 드래그하고 화면 가장자리에 가까이 가면 미리보기가 스크롤합니다. 놓을 때 한 번 재조판합니다. 다른 고정 오브젝트와 겹치거나 공간이 부족하면 기존 배치를 유지합니다. Escape로 드래그를 취소할 수 있습니다.

공개 프리셋 3개의 ZIP은 릴리즈에 함께 있습니다. 개인 저널 프리셋은 공개 플러그인과 분리해 보관할 수 있습니다. 템플릿에는 로고 원본이 포함되며 글꼴은 OS에서 검색하거나 대체 서체를 선택합니다.
