# 저널 편집 시작하기 — HanMark 3.0.2 개발본

## 어디서 여나요?

- 문서 툴바의 **PDF 오른쪽 → 저널 편집**
- **HanMark 내보내기 → 저널 편집 · 학술지 PDF → 저널 편집 열기**
- Obsidian 왼쪽 사이드바의 **HanMark 저널 편집** 아이콘
- 명령 팔레트에서 **HanMark: 저널 편집기 열기**

편집 중인 저널이 있으면 해당 탭으로 돌아갑니다. 새 원고를 시작하려면 저널 화면 위쪽의 **새 원고**를 누르세요.

## 시작 화면에서 원고 선택

### 현재 Markdown 노트로 시작

편집할 노트를 연 뒤 **저널 편집 → 현재 Markdown 노트로 시작**을 누릅니다. 원고 제목과 헤딩 단계 매핑을 확인하고 가져옵니다. 본문과 이미지의 복사본을 저널 프로젝트에 저장하며 원본 노트를 수정하지 않습니다.

다른 노트를 고르려면 저널 툴바의 **Markdown 가져오기**를 사용합니다. 원본 노트의 변경을 가져오려면 **Markdown 원문 다시 가져오기**에서 차이를 검토합니다.

### Word 원고로 시작

**Word 원고로 시작**에서 `.docx` 파일을 고르고, 파일 역할을 **본문**으로 확인한 뒤 **가져오기**를 누릅니다. 원고 내부의 표와 그림도 함께 가져옵니다. 저자가 별첨을 제공한 경우에는 같이 선택하고 역할을 지정할 수 있습니다.

### 저장한 프로젝트 열기

같은 볼트에서 저장한 저널 프로젝트를 이어서 엽니다. 다른 볼트에서 받은 프로젝트는 위쪽 **ZIP 열기**를 사용합니다. 처음부터 내용을 작성하려면 **빈 프로젝트에서 직접 작성**을 누릅니다.

## PDF를 만들기까지

1. **본문·템플릿 확인:** 불러온 본문을 편집하고 **저널 템플릿**에서 기본 HNMR 또는 사용자 템플릿을 고릅니다. 필요한 설치 글꼴은 조판할 때 자동 등록됩니다. 없는 글꼴만 대체 선택 창에서 지정합니다.
2. **원고 정보 / 발행정보 확인:** 제목·저자·초록, AOP 또는 권호 정보, DOI·날짜·교신저자·라이선스 연도를 확인합니다. **논문 말미 정보**에서 선언문도 입력합니다.
3. **조판:** PDF 미리보기를 생성합니다. **원고 정리·연결**, **표·그림·프레임**, **참고문헌**, **검사 결과**에서 필요한 수정을 확인합니다.
4. **검토용 PDF:** 아직 확인할 사항이 있어도 검수용 출력물을 저장할 수 있습니다. 최종 PDF는 필수 확인과 오류를 처리한 다음 내보냅니다.

기존 PDF 버튼의 1단·2단 A/B 출력도 그대로 사용할 수 있습니다. 저널 편집은 별도 프로젝트와 미리보기를 사용하는 학술지 편집 화면입니다.

## 간편 저널 템플릿

**저널 템플릿 → 기본 정보 → 로고 → 색상·글꼴 → 문구 → 미리보기·저장** 순서로 설정합니다.

- **HNMR 기본**은 원래 서체·색상·마스터를 유지합니다. **새 사용자 템플릿**은 HNMR 로고와 라이선스가 없는 일반 간행물로 시작합니다.
- 사용자 로고는 PDF·PNG·JPG를 지원합니다. PDF가 여러 쪽이면 사용할 쪽을 고릅니다. PDF는 원본 벡터를 보존하며 PDF·AF에 배치합니다. 화면 확인용 이미지가 출력 원본을 대체하지 않습니다. 비율을 유지하며 화면에 표시된 고정 영역에 맞춥니다.
- 글꼴은 본문·제목·보조정보 세 그룹을 선택합니다. **기존 서체 유지**는 HNMR의 혼합 서체를 유지합니다. 글자 크기·줄높이·자간·단 폭은 조판 엔진이 관리합니다.
- 문구는 `{year}`, `{copyrightYear}`, `{journal}`, `{volume}`, `{issue}`, `{page}` 등 표시된 변수를 사용할 수 있습니다. 값은 현재 원고의 발행정보에서 가져옵니다. 긴 문구는 미리보기에서 실제 글꼴로 넘침을 검사합니다.
- **일반 간행물**은 DOI·접수일·교신저자·학술 선언문을 필수로 요구하지 않습니다. 참고문헌 검사는 따로 켤 수 있습니다. 내용 누락과 넘침 검사는 항상 유지됩니다.
- 저장된 템플릿은 다른 원고에서 선택하거나 ZIP으로 교환합니다. 글꼴 파일은 템플릿 ZIP에 포함하지 않습니다.

기존 원고는 적용 당시의 템플릿과 글꼴을 보존합니다. 목록에서 템플릿을 고쳐도 기존 원고는 자동으로 바뀌지 않습니다. 적용을 취소하려면 저널 편집기의 **되돌리기**를 사용합니다.

## 설치 글꼴

Windows·macOS·Linux의 읽을 수 있는 설치 글꼴(TTF·OTF·TTC·OTC)을 탐색합니다. 새로 설치한 글꼴은 다음 플러그인 시작이나 **글꼴 목록 새로고침**에서 반영됩니다. 조판에 필요한 글꼴만 원고 프로젝트에 저장하므로 이후 OS 글꼴이 바뀌어도 이미 저장한 원고의 출력은 유지됩니다.

앱 내부 전용·클라우드 전용 글꼴은 OS 글꼴로 노출되지 않을 수 있습니다. 필요한 경우 **글꼴 파일 등록**으로 직접 가져올 수 있습니다. 다른 컴퓨터에서 프로젝트 ZIP을 열면 그 프로젝트에 보관한 글꼴을 사용합니다.

## Affinity에서 마무리하기 — 개발 중인 AF 내보내기

저널 편집 상단 **AF로 내보내기**를 누릅니다. 원고가 바뀌었으면 현재 내용으로 다시 조판한 뒤 내보냅니다.

**페이지 배치**의 기본값은 **두 쪽씩 나란히 (1–2, 3–4…)**입니다. 첫 페이지를 왼쪽에 놓고 좌우 마스터를 한 스프레드로 묶습니다. 마지막에 한 쪽이 남아도 빈 페이지는 추가하지 않습니다. **한 쪽씩**으로 바꿀 수도 있습니다. 기존 쪽번호와 왼쪽 단 → 오른쪽 단 → 다음 페이지의 본문 연결은 유지됩니다.

- **AF + 비교용 PDF + 원본 그림 (.zip)**: 압축을 풀고 `document.af`를 Affinity에서 여세요. `reference.pdf`는 HanMark 조판 기준본입니다.
- **Affinity 파일만 (.af)**: 편집 파일만 저장합니다. 그림은 파일 내부에 포함됩니다.
- **끝에 추가할 연결 페이지**: 0~3쪽을 선택합니다. 기존 마지막 본문 박스부터 추가 페이지의 왼쪽·오른쪽 박스까지 같은 본문으로 연결됩니다. 추가 페이지는 편집 여유 공간이므로 머리말·쪽수는 Affinity에서 마무리합니다.

본문이 박스보다 길어져도 텍스트가 삭제되지는 않습니다. 박스를 늘리거나 다음 박스를 연결하면 이어서 보입니다. 글자 크기를 자동으로 줄이지 않습니다. 표·그림은 별도 객체이며 본문 수정에 따라 자동 이동하지 않으므로 최종 위치를 확인하세요.

본문 박스는 단의 사용 가능한 작업 영역에 맞춥니다. 표·그림이 중간에 있으면 그 앞뒤 영역에서 박스를 나누며, 연결은 이어집니다. 교신저자 박스는 초록과 바깥 경계를 맞춥니다.

2쪽부터는 실제 AF 마스터와 자동 쪽수 필드를 사용합니다. **원고 정보 → 머리말 저자 표기 / 머리말 축약 제목**에서 홀수 쪽 머리말을 고칩니다. 짝수 쪽에는 저널명과 연도가 표시됩니다. **발행정보 확인**의 시작 쪽수와 AOP 설정이 함께 적용됩니다. Affinity에서 시작 쪽수의 홀짝을 바꿨다면 좌우 마스터 배정도 확인하세요.

이전 개발본에서 만든 AF를 처음 덮어쓸 때 `파일 소유권을 확인할 수 없음`이 나타났다면, 열린 문서를 **다른 이름으로 저장**해 편집 내용을 먼저 보존하세요. 수정된 생성기로 새로 내보낸 AF는 첫 덮어쓰기 저장에 필요한 파일 경계 정보를 포함합니다.

이 기능은 현재 **저널 화면의 실험 기능**입니다. 자른 그림과 본문 줄 안의 이미지는 PDF·IDML로 내보내세요. 글꼴 파일은 AF 패키지에 포함하지 않으므로 Affinity를 실행하는 컴퓨터에 해당 글꼴이 필요합니다. Affinity에서 수정한 내용은 Markdown·Word 원문으로 자동 역반영되지 않습니다.

### 원고 정보나 그림이 빠져 있을 때

익명 심사용 DOCX에는 제목·저자·교신저자 정보가 없을 수 있습니다. 오른쪽 **원고 정보 → 제목**, **발행정보 확인 → 교신저자 추가**에서 입력하세요. 출력 서식은 자동 적용됩니다. 검토용 PDF와 편집용 AF·IDML에는 입력 전까지 누락 표시가 남습니다.

Word 차트에 미리보기 이미지가 없는 경우에도 편집용 내보내기는 해당 위치와 캡션을 보존합니다. **Figure N 원본 연결**에서 실제 그림을 지정하거나 Affinity에서 표시된 자리를 교체하세요. 자리표시자는 원본 그림 복원 완료를 뜻하지 않으며 AF 패키지 검사 보고서에도 누락 상태가 기록됩니다.
