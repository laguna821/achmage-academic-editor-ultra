# R-027 — 검토 가능한 원고 정리와 DOCX·Markdown 공통 저널 입력

작성일: 2026-09-16. 상태: 구현 및 로컬 개발 검증. 공개 배포 승인이 아니다.

## 질문과 범위

R-026까지의 본문·표·그림 조판에 실제 저자 원고의 정리, 개체 식별과 순서, 검토 화면을 연결한다. DOCX와 Markdown을 같은 저널 문서 모델에 넣고, 자동 정리의 근거와 원문을 보존한다. 사용자가 지적한 Introduction/References 단 시작 여백, 캡션 분리, 삽입 지시문, 중복 표제와 필수 선언문을 다룬다.

기준은 공개 2.6.1 `a31a191d21cbb21e45d6ce76bdf187ca5b2502ff` 위의 기존 3.0.0 개발 작업이다. 이전 미커밋 변경을 보존했다. 이번 산출물은 3.0.0 개발본이며 태그·Release를 발행하지 않는다. macOS 실기 검증은 사용자의 기존 결정대로 필수 조건에서 제외하며 CI는 유지한다.

## 구현된 계약

### 1. 원본과 정리 결과를 함께 보존

- 독립된 `Insert/Place Figure/Table N [About] Here` 문단은 높이가 없는 위치 표식으로 바꾼다. 일반 문장 속 표현을 삭제하지 않는다. 대상 번호가 중복되거나 없으면 편집자에게 연결을 요청한다.
- 바로 뒤의 표·그림을 묶는 `Tables`/`Figures` 표제만 정리한다. 같은 단어를 쓰는 일반 절 제목은 유지한다.
- 표 첫 병합 행의 명확한 번호·제목은 표 밖의 캡션으로 옮긴다. 안팎 캡션이 모두 있으면 선택 화면에서 확정한다. 원본 행과 이전 캡션은 기록에 남는다.
- 번호와 제목이 서로 다른 Word 문단에 있는 캡션도 하나로 붙인다. 캡션·그림·주석은 같은 묶음으로 배치한다. 명시적 캡션에 대응하는 그림이 없으면 검토용 자리 표시와 오류를 함께 출력한다.
- 정리 기록은 원본 노드, 변경 이유, 대상과 적용 상태를 저장한다. 되돌리기는 원본을 복구하며 이후에 추가한 표 주석·데이터를 보존한다.

이 규칙은 저자의 뜻을 추측해 모든 원고를 고치는 기능이 아니다. 불분명한 표 구조, 여러 개체에 해당하는 번호와 누락 자료는 검토 목록으로 남긴다.

### 2. 최종 배치 번호와 본문 연결

개체 ID는 번호와 독립적이다. 저자의 원래 번호는 `sourceNumber`에 보존하고, 출력 번호는 페이지의 실제 읽기 순서로 계산한다. 전체 폭 항목이 나누는 각 영역에서 왼쪽 단을 읽고 오른쪽 단을 읽는다. 표·그림과 부록 접두사별로 별도 순번을 사용한다.

명확한 본문 호출을 ID에 연결해 출력 번호와 함께 바꾼다. 중복·모호한 연결은 편집자가 결정한다. 번호 변경으로 줄바꿈이 달라질 수 있으므로 조판과 번호 계산을 최대 5회 반복한다. 수렴하지 않으면 오류를 표시한다. 시간 제한이나 임의 선택으로 결과를 확정하지 않는다.

전체 회귀에서 재번호화된 호출 문구가 다음 조판의 원문 번호 검색에 다시 걸려 서로 다른 개체를 끌어오는 결함을 발견했다. 연결된 호출은 ID만 사용하고, 원문 번호 검색은 아직 연결되지 않은 텍스트에만 적용하도록 수정했다. 번호가 서로 교환된 경우에도 위치 대상이 그대로 유지되는 회귀 테스트를 추가했다.

### 3. 참고문헌과 원고에 없는 선언문

참고문헌은 첫 저자의 성 또는 기관명에 해당하는 정렬 키로 정렬한다. 정렬 확인과 APA 서지 정보 확인은 별도 상태다. Word에서 한 항목을 여러 문단으로 나눈 경우에는 연결 문단을 함께 이동하며 원문 문단 ID를 모두 보존한다. 저자·날짜 구조를 확실하게 해석하지 못하면 수동 키를 입력한다. 알파벳 정렬만으로 APA 7 전체 규정 준수를 확정하지 않는다.

Data availability, Funding, Conflict of interest는 확인이 필요한 기본 항목이다. Acknowledgments, Ethics, Author contributions, 사용자 정의 항목도 지원한다. 표시 여부·제목·내용·순서와 생략 사유를 편집하고, 확인된 내용은 References 앞에 일관된 스타일로 삽입한다. 빈 기본 항목이나 미확인 내용은 최종 내보내기 전에 알린다. 원고에 없는 문구를 출판 PDF에서 채우지 않는다.

### 4. 그림 원형과 로컬 OCR

Word 차트에 원래 미리보기 이미지가 있으면 그것을 사용한다. 원래 미리보기가 없는 차트를 다른 형태로 다시 그려 복원했다고 처리하지 않는다. 특히 3D 차트는 편집자가 원본 이미지를 제공해야 한다.

이미지 내부의 `Figure N`/`Table N` 후보는 Tesseract.js/core 7.0.0과 고정한 영문·한글 언어 자료로 로컬 검사한다. 코드·WASM·언어 자료는 빌드에 포함하고 해시를 확인한다. 실행 중 외부 CDN, AI 또는 OCR API를 호출하지 않는다. 긴 변은 최대 2,400픽셀로 검사한다.

- 낮은 확신도 후보도 검토 대상으로 보여 주지만 자동으로 자르지 않는다.
- 가장자리 후보와 그림 사이에 폭 전체가 빈 띠가 있는 경우만 자동 크롭안을 제안한다.
- 편집자는 원본·후보 영역·예상 결과를 보고 유지 또는 크롭을 확정한다. 수동 경계 조절도 가능하다.
- 원본 이미지 바이트는 유지하고 정규화 좌표와 원본 해시에 연결된 크롭만 저장한다. 이미지가 바뀌면 이전 크롭 확인을 무효화한다.
- 캡션이 아닌 축·범례·통계 기호의 판단과 OCR 미탐지는 사람의 시각 검토가 필요하다. OCR이 모든 중복 캡션을 찾는다는 보장은 없다.

### 5. Markdown을 같은 조판 엔진에 연결

현재 Obsidian 노트에서 저널 프로젝트를 만드는 명령과 입력 옵션을 추가했다. 제목·헤딩 단계 매핑, 강조·링크·목록·인용/콜아웃·표·코드·로컬 이미지와 위키 이미지 임베드를 구조화한다. 연속 이미지 문단은 각각 독립된 그림으로 만든다. 원본 노트에 쓰지 않고 문서·이미지의 스냅샷을 프로젝트에 보관한다.

재가져오기는 마지막 원본 스냅샷과 비교한다. 원본이 그대로인 부분의 편집자 수정을 유지하고, 원본에서 변경·추가·삭제된 문단과 순서·메타데이터를 검토 목록에 올린다. 수락한 변경만 적용한다. 참고문헌 정보도 해당 변경을 수락한 뒤 갱신한다. 보류된 재가져오기 검토가 있으면 다음 재가져오기를 시작하지 않는다.

DOCX·Markdown의 정리 결과는 동일한 문서/표/그림/캡션/서지 모델, HNMR 마스터, 레이아웃과 미리보기·내보내기로 이어진다. 일반 Markdown 파일의 모든 저널 메타데이터가 자동 추론되는 것은 아니다.

### 6. 단 시작과 기준선

Introduction·References 등 제목이 새 흐름 영역의 첫 항목이면 제목 앞 간격을 없앤다. 첫 장의 초록 아래, 새 페이지·단, 전체 폭 항목 아래와 마지막 단 균형 조정 후의 새 위치에 같은 규칙을 적용한다. 기준선 맞춤으로 필요한 보정은 제목 아래에 적용한다.

첫 페이지에서 제목과 그림이 하나의 묶음으로 시작하는 경우에도 본문이 없는 영역 위에 그림 앞 간격을 추가하지 않는다. 본문 중간의 표·그림 앞뒤 간격은 계속 예약한다. 같은 영역의 양쪽 본문은 공통 기준선 원점을 사용한다.

### 7. 저장과 호환성

저널 프로젝트 스키마는 2다. 기존 스키마 1 프로젝트는 새 정리·번호·참고문헌 정렬 정책을 끈 채 읽는다. 기존 PDF가 열기만 해도 다른 정책으로 바뀌지 않는다. 원본, 정리 기록, OCR 검토와 Markdown 기준 스냅샷을 프로젝트 저장에 포함한다. 기존 Markdown/HWPX/HTML 내보내기와 PDF A/B 모드는 유지한다.

## 검증 방법과 산출물

원본 manuscript 22편과 이전 평가 후 보존한 회귀 원고 6편을 다시 출력한다. 이 6편은 이미 확인한 회귀 자료이며 새로운 미관측 평가라고 부르지 않는다. 별도 Figure/Table DOCX 또는 출판본의 내용을 생성 입력으로 쓰지 않는다. 이전 `quality-*`, 첫 평가·규칙 고정 파일은 보존하고 새 결과에 `phase3-*` 이름을 사용한다.

검증은 원본 DOCX 목록, 가져온 항목, 원문 식별자, PDF의 실제 글자/그림과 좌표를 구별해서 검사한다. 정리 기록만 존재한다고 원문 보존을 통과시키지 않는다. 새 캡션의 PDF 글자, 배치 순서에 따른 번호, 제목 영역 시작과 본문 경계를 검사한다. 원본 미리보기가 없는 Office 차트는 자리 표시가 그려져도 원본 복원 통과로 세지 않는다.

Achmage의 긴 Educational Harness Engineering 원고는 원본 Markdown 토큰을 별도 파서로 읽어 텍스트와 이미지 발생 횟수를 대조한다. 원본 SHA-256은 `5395ac7bf7058bd632337d33df47bedde7c6db8525b45ead4f873331a59c0e9f`다. 한글·이모지 글꼴은 로컬 테스트에만 등록하고 배포하지 않는다.

실제 Obsidian 검사는 별도 테스트 볼트와 프로필에서 진행한다. 개발본의 명령·미리보기·AOP/권호 입력·선언문 확인·OCR 크롭·저장/재열기·Markdown 재가져오기를 확인한다. 사용자 실사용 볼트에는 설치하지 않는다.

재현 명령:

```text
npm run check
node scripts/test-journal-engine.mjs
node scripts/test-journal-ocr.mjs
node scripts/test-journal-host.mjs
node scripts/test-journal-phase3.mjs
node scripts/audit-journal-markdown.mjs
python scripts/build-journal-phase3-review.py <private research folder>
```

실제 원고·글꼴 경로는 로컬 환경 변수와 무시되는 입력 목록으로 전달한다. 개발 소스에는 원고나 유료 글꼴을 넣지 않는다. Windows에서는 테스트 Chromium 대신 `HANMARK_TEST_BROWSER=edge`를 사용할 수 있다.

- R-026의 개발 원고 원문 통과 21/22와 이번 19/22는 차트 처리 기준이 다르다. 이번에는 원래 미리보기 없는 차트를 근사 도형으로 다시 그린 결과를 원형 복원으로 인정하지 않아 107·87번도 미해결로 기록했다.

발행 메타데이터·필수 선언문, 모호한 서지 정렬 키와 본문 참조, 긴 러닝 헤더 및 미확정 표 정리는 별도 편집 오류로 남는다. PDF 상세 검사 통과는 이 내용에 대한 편집자 승인을 대신하지 않는다.

산출물은 무시되는 `test-artifacts/journal/`에 둔다. `phase3-before-after.pdf`는 대표 네 사례의 전후 비교, `phase3-achmage-markdown.pdf`는 실제 Markdown 조판, `phase3-review.json/.md`는 검토 목록이다. `hanmark-3.0.0-phase3-dev.zip`에는 플러그인·고지·시험 안내만 담고 원고와 유료 글꼴은 넣지 않았다. ZIP의 파일 해시를 다시 읽어 빌드와 일치함을 확인했다. 공개 릴리스 또는 실사용 볼트 설치는 수행하지 않았다.

## 남은 범위

원본이 없는 차트·이미지, 불명확한 통계 표의 의미 구조, Wingdings 등 모호한 기호, 본문에 없는 발행 정보는 편집자가 확인해야 한다. 편집 가능한 검토 화면을 제공하는 것과 원본 자료가 복원되는 것은 별개다. 역사적 PDF의 모든 줄바꿈·픽셀을 재현했다고 주장하지 않는다.

R-022의 확장 Crossref 일괄 교정 큐, APA 모든 자료 유형의 완전 자동 판별, 임의 출판사 첫 장 마스터는 후속 범위다. R-026에서 후속으로 적었던 Markdown-to-journal 입력은 이번 단계에서 구현했다. 조판 엔진과 로컬 OCR에는 AI 토큰이 들지 않는다.

## 근거와 변경 이력

원본 마스터·APA 표·주석 규칙의 조사 근거는 R-020–R-026을 유지한다. 이번 문서는 새 APA 규칙을 선언하지 않고 정리·검토·배치의 구현 및 로컬 결과를 기록한다. OCR 의존성·언어 자료 출처와 라이선스는 `THIRD_PARTY_NOTICES.md`, `assets/journal/ocr/manifest.json`과 `LICENSE`에 기록한다.

- 2026-09-16: 공통 입력, 원본 보존 정리, OCR 검토, 최종 번호, 선언문과 단 시작 보정 구현. 이전 회귀 산출물을 보존하고 별도 개발 결과를 생성.

## 후속 수정 — 실제 사용 진입점

사용자 시험에서 명령 팔레트에만 새 저널 모드가 있고 기존 툴바와 내보내기 창에는 보이지 않는 문제가 확인됐다. 기능 내부 검증에 비해 첫 진입 동선 검증이 빠졌다.

- 문서 툴바 PDF 오른쪽에 **저널 편집**, 내보내기 창에 **저널 편집 · 학술지 PDF / 저널 편집 열기**, 왼쪽 리본에 저널 아이콘을 추가했다.
- 세 진입점과 기존 명령은 같은 편집기 열기 함수를 사용한다. 이미 열린 저널 탭을 활성화하며 편집본을 보존한다.
- 빈 프로젝트에는 **현재 Markdown 노트로 시작 / Word 원고로 시작 / 저장한 프로젝트 열기**와 사용 순서를 보여 준다. 직접 작성도 가능하다. Markdown은 현재 편집기의 최신 내용을 가져오며 노트가 없으면 설명과 함께 선택을 비활성화한다.
- 새 원고를 만들 때 이전 검사 패널이 남던 문제를 수정해 원고 정보 패널로 돌아간다.
- [빠른 사용법](../journal-quick-start.ko.md), README와 개발 릴리스 노트에 진입 위치를 추가했다.

`npm run check`의 328개 테스트·lint·타입·빌드·Community·파일 일치 검사, 기존 내보내기 UI 검사가 통과했다. 격리 Obsidian에서 실제 버튼을 클릭해 Word 파일 선택·본문 가져오기, 프로젝트 목록, 직접 작성, 툴바·내보내기 진입, 기존 프로젝트 보존과 탭 재사용, Markdown 가져오기·OCR 크롭·재가져오기까지 통과했다. 조판 미리보기와 내보내기 동일성 검사도 이 통합 흐름에서 유지한다.
