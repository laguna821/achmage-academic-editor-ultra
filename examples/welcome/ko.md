## 연구를 위한 마지막 한 걸음

논문을 쓰는 이유는 연구를 전하기 위해서입니다. 편집은 독자가 그 연구를 발견하도록 도와야 합니다. 명확한 제목, 그림과 떨어지지 않는 캡션, 숨 쉴 간격을 가진 표는 각각 작은 결정이지만, 모이면 읽고 싶은 지면이 됩니다. 이런 결정을 페이지마다 반복하는 데 쓰는 시간은 정작 논증을 다듬는 데 쓰고 싶었던 시간이기도 합니다.

Academic Editor Ultra는 익숙한 글쓰기와 세밀한 조판을 같은 흐름에 놓습니다. Markdown 모드에서는 노트가 글의 원본입니다. 조판 프로젝트는 배치, 선택한 템플릿과 검토 기록을 보관합니다. 디자인 파일에 옮겨 적었던 문장을 다시 가져올 필요 없이, 노트로 돌아가 문단을 수정하고 다음 교정본을 만들 수 있습니다.

### 설명서를 다 읽기 전에 시험해 보세요

이 노트 맨 위의 `aaeu-title` 속성을 찾아 자신이 원하는 제목으로 바꿔 보세요. 저널 작업 화면에서 **조판**을 누르면 첫 페이지 제목이 달라집니다. 글꼴과 위치, 주변 간격은 선택한 템플릿이 처리합니다. 다음에는 `aaeu-abstract` 안의 문장 하나를 바꾸고 다시 조판해 보세요.

이 작은 실험이 전체 기능의 핵심입니다. 익숙한 편집 위치에 정보를 한 번 입력하면, 문서는 그 정보가 들어갈 자리를 일관되게 정합니다. Figure 1은 교정본 다음으로 이어지는 작업 흐름을 보여줍니다. 저자 이름과 소속, 교신저자 정보, 러닝헤드, 참고문헌 앞에 오는 선언문도 같은 방식으로 다룰 수 있습니다.

![글쓰기에서 조판과 최종 편집으로 이어지는 작업 흐름](assets/workflow.svg)

## 익숙한 문법으로 작성하세요

본문에는 평소 쓰던 Markdown을 사용합니다. 헤딩과 문단, 강조, 목록, 이미지 링크와 표를 작성하면 됩니다. 논문 제목은 전용 속성에 넣고, 첫 본문 절은 두 번째 단계의 헤딩으로 시작합니다. 하위 절에는 다음 헤딩 단계를 씁니다. 글을 쓰기 전에 텍스트 박스를 그리거나 각 문단이 끝날 위치를 결정할 필요는 없습니다.

그림은 볼트 안에 원고와 함께 둘 수 있습니다. 표준 HTTPS 이미지 링크도 지원합니다. 이 샘플은 처음 시험하는 과정이 원격 서버에 의존하지 않도록 로컬 그림을 사용합니다. 실제 작업에서는 조판에 사용한 이미지의 바이트를 프로젝트에 보관합니다. 같은 주소의 원격 그림이 바뀌었다면 새로고침으로 새 버전을 가져올 수 있습니다.

캡션은 설명하는 대상 가까이에 둡니다. 표 제목은 Markdown 표 바로 앞에, 표 주석은 바로 뒤에 작성하세요. 가져오기 과정은 이 관계를 보존하고, 조판은 제목·표·주석을 한 묶음으로 다룹니다. 원고의 명확한 구조는 읽기 좋은 지면으로 가는 가장 단순한 출발점입니다. Table 1에서 구체적인 매핑 예시를 확인할 수 있습니다.

Table 1. 원고에서 한 번 입력한 정보가 배치되는 자리

| 원고에 입력할 정보 | 출력물의 위치 |
| --- | --- |
| 제목 속성 | 첫 페이지 제목 |
| 초록 속성 | 초록 박스 |
| 그림 캡션 | 해당 그림과 함께 |
| 표 주석 | 표 바로 아래 |
| 말미 선언문 | 참고문헌 앞 |

Note. 이 표는 정보 매핑의 예시이며 성능 측정 결과가 아닙니다. 같은 내용을 두 편집기에 각각 관리하지 않습니다.

### 원고와 모양을 구분해 두세요

템플릿은 일관된 시각적 정체성을 제공합니다. 딥 네이비의 **Journal of Achmage**와 틸·핑크의 **Journal of Command & Space**를 전환해 보세요. 두 프리셋에는 벡터 PDF 로고가 포함되어 있습니다. 상단 **템플릿** 목록에서 선택하면 즉시 적용되어 원고는 그대로 두고 지면의 정체성이 달라집니다. 페이지의 기본 구조를 다시 만들지 않고도 로고, 키컬러, 초록 배경과 반복되는 발행 문구를 고릅니다. 원고 속성은 논문마다 달라지는 정보를 담습니다. 비워 둔 재정의 문구는 템플릿을 상속하고, 명시적인 숨김 속성은 해당 항목을 의도적으로 제외합니다.

전용 속성의 전체 목록은 저널 작업 화면에서 확인할 수 있습니다. 이 설명서는 실제로 쓰는 속성을 채워 두었습니다. 더 많은 저자, 오른쪽 정보 항목, 말미 문구가 필요하면 속성을 추가할 수 있습니다. 짧은 안내문과 복잡한 학술 원고도 같은 조판 경로에서 출발합니다.

## 지면이 글을 따라오게 하세요

조판기는 원고의 구조를 바탕으로 작업합니다. 본문은 왼쪽 단, 오른쪽 단, 다음 페이지로 이어집니다. 표와 그림은 각각 필요한 배치 공간이 다릅니다. 어떤 대상은 한 단에, 다른 대상은 본문 전체 폭에 놓이는 편이 읽기 좋습니다. 캡션과 주석도 이 판단에 포함되어, 편집자가 나중에 따로 찾아 붙이는 문단이 되지 않도록 합니다.

좋은 교정본은 확인하기 쉽습니다. 큰 제목 바로 아래 소제목이 오는 간격, 표 주변의 여백, 초록과 오른쪽 정보가 함께 놓이는 첫 장을 살펴보세요. 이런 세부는 독자의 읽기를 돕기 때문에 중요합니다. 이 설명서는 일반 조판 엔진으로 출력하므로 사용자의 원고도 같은 경로를 거칩니다. Figure 2는 주요 정보가 배치되는 위치를 설명합니다.

![저널 지면에 배치되는 원고 정보의 구조도](assets/editorial-map.svg)

Figure 2. 원고 정보에는 일관된 자리가 있습니다. 이 그림은 매핑을 설명하는 구조도이며 실제 출력 화면의 스크린샷은 아닙니다.

### 소프트웨어가 알 수 없는 사실은 확인하세요

투고 시스템에 기록된 날짜는 편집자가 확인할 사실입니다. DOI, 연락처, 데이터 공개 선언도 마찬가지입니다. 전용 속성과 검토 패널은 이런 정보를 입력하고 확인하는 수고를 줄이면서도 정확성을 결정하는 권한을 편집자에게 남깁니다.

APA 중심 검사와 참고문헌 도구는 확인할 항목을 드러냅니다. Crossref 조회는 대조할 후보를 제공할 수 있지만, 그럴듯한 결과가 곧 동일 문헌이라는 증거는 아닙니다. 원문을 확인하고 맞는 교정을 반영한 뒤 다시 조판하세요. 목표는 편집자의 판단을 더 쉽게 적용하도록 돕는 것입니다. Table 2는 원문과 최종 검토의 역할을 구분합니다.

Table 2. 원본과 최종 검토에서 각각 확인할 것

| 작업 | 주된 위치 | 확인할 내용 |
| --- | --- | --- |
| 문장과 원고 정보 | Markdown 노트 | 의미, 이름, 발행 사실 |
| 시각적 정체성 | 저널 템플릿 | 로고, 색상, 반복 문구 |
| 표와 캡션 | 원고와 교정본 | 수치, 설명, 읽기 좋은 묶음 |
| 참고문헌 교정 | 원문과 조회 도구 | 문헌 식별, 저자 순서, DOI |
| 마지막 디자인 수정 | Affinity 편집본 | 줄바꿈, 흐름, 넘치는 본문 |

Note. Affinity 파일은 후속 편집본입니다. 그 파일에서 바꾼 내용은 Markdown 원문으로 자동 역변환되지 않습니다.

## 마지막 손길은 편집자에게

아주 가끔은 수동 수정이 가장 빠릅니다. 그때 Affinity 파일을 내보내세요. 본문 프레임은 단과 페이지 사이에 연결되어 있고, 지원되는 그림과 다른 오브젝트는 개별적으로 선택할 수 있습니다. 프레임을 살펴보고 필요한 부분을 다듬은 뒤 Affinity에서 저장합니다.

내보낸 샘플의 본문 텍스트 박스를 선택해 보세요. 다음 단과 다음 페이지로 이어지는 연결을 확인합니다. 그림을 선택하면 독립된 오브젝트임을 볼 수 있습니다. 마스터 스프레드와 페이지 번호 필드도 살펴보세요. 첫 화면의 모양뿐 아니라 이런 작업 구조가 실제 편집 인계를 가능하게 합니다.

PDF는 조판 결과를 확인하는 교정본입니다. Affinity는 자체 텍스트 엔진을 사용하므로, 수정한 뒤 줄바꿈과 마지막 텍스트 박스를 확인하세요. 넘치는 글은 이야기 안에 남아 있으며 보여 줄 프레임 공간이 더 필요한 상태입니다. 연결된 프레임을 늘리는 것은 원고를 줄이거나 버리는 것과 다릅니다.

### 첫 작업을 끝까지 이어가세요

제목과 초록 한 문장을 바꾼 뒤 새 교정본을 만드세요. 두 표와 주석을 확인하고 PDF를 저장합니다. 이어 Affinity 편집 패키지를 내보내 문서를 열고, 연결된 본문 프레임을 선택해 작은 수정을 합니다. 저장한 결과를 다시 열면 원고에서 최종 편집까지의 한 사이클을 경험한 것입니다.

수정한 샘플은 참고 자료로 남겨 두세요. **설명서 원고로 시작**은 기존 샘플을 다시 열고, **새 사본 만들기**는 별도의 출발점을 제공합니다. 준비가 되었다면 새 Markdown 원고를 만들거나 저자의 Word 원고를 가져오세요. Word는 기존의 편집·검토 경로를 따르고, Markdown은 계속 노트를 원본으로 사용합니다.
